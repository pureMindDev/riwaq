# Letter pronunciation audio

**Status (2026-11-13): all 28 letters have an individual recording of the letter's NAME by a native Arabic speaker (Lingua Libre, published on Wikimedia Commons). They are NOT Tajweed-verified and they are not makhraj demonstrations. A qualified Qur'an teacher should review them before this is presented as Qur'anic pronunciation teaching.**

## Sources and licences
- Originals: Lingua Libre recordings on Wikimedia Commons, file names `LL-Q13955 (ara)-<speaker>-<letter>.wav`. Each is a single letter name ("alif", "baa", ...).
- Readers and licences: AlNatiq, CC0 (23 letters); Rashed Aljahdali, CC BY 4.0 (ز ظ); Zinou2go, CC BY-SA 3.0 (ب د و). Per-letter detail, with the Commons link of each original, is in `frontend/public/audio/letters/manifest.json` and `CREDITS.txt`.
- How we obtained them: Commons itself could not be reached from the build environment, so the files were taken from the public repository https://github.com/techjewel/kiddo (`sounds/arabic/names/`, with `sounds/CREDITS.md` naming each original, author and licence). That repository trimmed and loudness-levelled each clip and encoded it as AAC; those are the only changes. The credit letters in that file were checked programmatically against our curriculum letters (all 28 match). The licences were NOT re-checked on the Commons file pages; please spot-check a few (especially the CC BY-SA ones) before launch.
- Obligations: CC0 none. CC BY 4.0 and CC BY-SA 3.0 need credit to the author, a licence link and a note of changes (all in `CREDITS.txt`, linked from the lesson page). CC BY-SA 3.0 also means the adapted clips (ba, dal, waw) must stay under CC BY-SA 3.0; this applies to those audio files, not to the app code.
- Rejected sources: the older full-alphabet recording (a single 31 s file split into 28 clips; not used), `bubblesinarabic/alphabets-audio` (no licence, unknown speaker), `vurado0/arabic-alphabet` (computer speech), Kaggle "Audio Dataset for Arabic Letters" (no licence or provenance stated), commercial teaching sites (all rights reserved).

## How it works
- `frontend/public/audio/letters/manifest.json` maps a letter id to its recording: `"ba": { "file": "ba.mp3", "reader": "...", "verifiedBy": "..." }` (a plain `"ba": "ba.mp3"` also works).
- Letter ids are the 28 ids in `backend/config/foundationCurriculum.js`. One id = one letter = one recording; the four written shapes of a letter (alone/start/middle/end) share that single recording. No backend or database change was needed.
- On each letter card: a speaker button next to the letter name (play / stop, shows a filled "playing" state) and the big letter itself (tap to replay from the start). Both appear **only** when the letter is listed. One shared player means two clips never overlap; clips stop when the tab is hidden or the page is left. A listed file that cannot load turns its button into a greyed-out "Recording of X is not available" control and the page keeps working.
- `npm run check:audio` (in `frontend/`) validates the manifest: known letter ids, safe file names, `.mp3`/`.m4a` only, file exists, looks like real audio, no file or identical bytes reused for two letters, and flags entries without `verifiedBy`. `-- --all` also fails if any letter is missing.

## Recording guidance (for replacing the clips with a qualified teacher's recordings)
The 28 ids: alif, ba, ta, tha, jim, hha, kha, dal, dhal, ra, zay, sin, shin, sad, dad, tta, zha, ayn, ghayn, fa, qaf, kaf, lam, mim, nun, ha, waw, ya.

Recording guidance (for the reader): say the letter's sound clearly with its proper makhraj, without an added vowel where possible (teachers commonly use a sukun-style stop or the letter with a short "a" support; the teacher decides and applies the same convention to all 28); about 1-2 seconds, one letter per file, quiet room, no music, trimmed silence, mono 44.1 kHz MP3 around 64 kbps (each file is tens of KB). Pay special attention to the confusable pairs: ث/س/ص, ذ/ز/ظ, ح/ه, خ/غ, ع/أ, ط/ت, ض/د, ق/ك.

## Where to store the files
Keep them in `frontend/public/audio/letters/` in the repository: 28 small files total under 2 MB are served by the same static host as the app, need no new service, no extra cost, and are cached by the browser. Move them to a CDN or object storage only if the total grows large; that is a change to one base URL in `src/lib/letterAudio.js`, so decide it when needed. Make sure the host returns a real 404 for a missing file (a host that returns `index.html` for it is handled as "not available", but gives a slower, less clear failure).

## What was tested (2026-11-13)
Real recordings: all 28 decode and play to the end in Chromium (3 rounds); 32 browser checks passed (correct file requested per letter on desktop and 375 px, playing state, replay, no overlap, keyboard, 44 px targets, missing file, empty/malformed manifest). Not tested: iOS/Safari and real phones, screen readers, and whether each clip says the correct letter (checked only by provenance; nobody listened).

## Makharij, "Check me" and "Record & compare" (added 2026-11-13/14)
- Each letter card in a letters lesson shows the **Tajweed/Qaida-style target** (the letter with fatha, e.g. بَ; alif as أَ) and a "Where it is made" note (articulation area + place) from `MAKHRAJ` in `backend/config/foundationCurriculum.js`. The notes are my textbook summary of the standard makharij and are **not reviewed by a qualified Tajweed teacher**; have one check all 28.
- **Check me (beta)** listens once with the browser's Arabic speech recogniser (Chrome, Edge, Safari) and turns the card **green** ("Correct: I heard ...") or **red** ("Not quite: I heard ..."; "I did not hear a letter") until the learner gets it. `frontend/src/lib/letterCheck.js` accepts only the bare letter, the letter + ā, or its Arabic name; longer words and other letters are misses. **Limits:** the recogniser is built for words, may confuse similar letters (ح/ه, ص/س, ق/ك, ط/ت, ض/د ...) in either direction, and judges what it *heard as text*, not the makhraj or Tajweed. The browser may send the voice to its speech provider, and the card says so. It is not available in browsers without speech recognition (e.g. Firefox).
- **Record & compare** records the learner (max 5 s) and plays it back beside the reference by ear; that recording stays in the browser tab and is never uploaded.
- What was tested: the matching rules (25 frontend unit tests) and the whole red/green flow in a real browser using a **scripted stand-in for the speech recogniser** (all 28 letters go green for their own letter and red for a different one; no speech; blocked service; cancel; no recogniser). **Not tested: real human speech with a real recogniser**, so the real-world accuracy of Check me is unknown. Test it yourself in Chrome, letter by letter, before relying on it.
- A true Tajweed check (judging makharij) needs a model validated on isolated letters with teacher-marked learner recordings; see `docs/RECITATION.md`.
- Better reference audio (the letter with fatha, in makhraj style, by a qualified reader) is still missing: no openly licensed set was found, and none can be generated here. Replace entries in `manifest.json` when recorded.

## AI letter check with Quran Muaalem (added 2026-11-14)
- `engine/` is a small Python service that wraps the open-source Quran Muaalem model. The backend route `POST /api/letters/check?letter=<id>` forwards one short recording to it (config `LETTER_ENGINE_URL`, `LETTER_ENGINE_KEY`); `GET /api/status` reports `letterCheck.available`. When available, the letter card's **Check me (AI)** records up to 4 s and shows green (right letter), red (a different letter, with what was heard), or red with articulation notes (right letter but, for example, light instead of heavy). Without an engine, the browser-speech beta is used. Setup, licence conditions and the measuring tool are in `engine/README.md`.
- **Tested:** the decision logic against the real phonetizer for all 28 letters (28 distinct expected sounds), the engine's HTTP layer with a fake model (key, size/length limits, bad audio, silence), the backend route (107 backend tests), and the whole red/green flow in a browser against a scripted stand-in engine. **Not tested: the real model.** It could not be downloaded in the build environment, so whether it separates Alif from Ta, ح from ه, ص from س in real voices is unmeasured. `engine/evaluate.py` measures it on your own recordings; do that before relying on it. The model's authors report a 75.8% Tajweed F1 on their benchmark and say it is for assistance only.
- Licence conditions of the model (QML 1.0): disclose AI use (the card does), no ads or ad tracking, free path to core features, comply with Islamic Sharia provisions.

## Quiz: listening and spoken questions (added 2026-11-19)
- A letters lesson's quiz now asks every letter two ways: **see it, give its name** (as before) and **hear it, pick the letter** (the recording plays; the letter is not printed). With the AI letter engine configured it also asks **four spoken questions** per lesson ("Say this letter aloud", shown with fatha); the letters that are hardest to tell apart (ح خ ث ج ... see `SAY_PRIORITY` in `backend/services/foundationService.js`) are picked first. With no engine, the spoken questions are simply absent and the quiz is names + listening.
- Pass mark is unchanged (80% of ALL questions). With 7 letters that is 18 questions (7 + 7 + 4), so skipping every spoken question scores 14/18 and fails: a learner must get at least one spoken question green (and everything else right), or more if they miss others. A spoken question can be retried as often as needed before submitting.
- **A spoken question cannot be claimed by the browser.** When the checker says "match", the backend returns a signed receipt (`proof`: HMAC of learner id, letter and expiry, valid 30 minutes; `backend/utils/voiceProof.js`). The quiz submission must include it; another learner's receipt, another letter's, an expired or edited one all score as wrong. Nothing is stored (no database change). Set `LETTER_PROOF_SECRET` when running more than one server, otherwise receipts end when the process restarts.
- Old saved results (total 7) stay valid; new attempts record out of 14 (no engine) or 18 (with engine).
- **Listening questions depend on the recordings.** If a clip does not load, the question says so and cannot be answered; the 80% rule absorbs one or two such misses but a broken clip is a real problem for the learner. Ba is currently such a clip (below).
- **The spoken questions rely on an AI checker whose accuracy on real voices has not been measured here.** A false red costs the learner retries; a false green lets a wrong pronunciation count. Measure with `engine/evaluate.py` before treating the result as a grade.
- Tested: 16 + 4 new backend tests (grading, forgery attempts, receipts, served questions carry no answers, end to end through the real routes and MongoDB: 111/111), and a real-browser run (desktop and 375 px phone, fake microphone, scripted engine stand-in): 38 checks incl. green/red, retries, engine down, 14/18 fail, 15/18 pass, 18/18 and Complete lesson. Not tested: the real model, real voices, iOS/Safari.

## Recording quality check and import tool (added 2026-11-19)
- `npm run check:audio:quality` (needs ffmpeg) measures each clip: seconds of actual sound, peak level, clipping, length. It flags a clip with under 0.1 s of sound, near silence, over 3 s, or clipped. It **cannot** tell whether the right letter is spoken or the makhraj is right.
- **Result on the shipped clips (2026-11-19): 27 pass, 1 fails: `ba.m4a`.** It is a 0.04 s burst (the "b" release) followed by about 0.3 s of low background noise and no vowel, the "crack" a learner hears. Re-levelling cannot fix it (it would only raise the noise). The other 27 have 0.12 to 0.35 s of sound; the shortest are waw, sad, kha and hha (0.12 to 0.14 s). I have not listened to any clip; the other 27 simply are not objectively broken.
- **Ba needs a replacement recording.** The Commons file page and other readers' versions of ب were not reachable from the build environment, and the techjewel/kiddo repository has no other clean source (its older `arabic/letters` set is the 31 s alphabet recording split into 28 pieces, which we do not use). Options: (1) download another reader's ب from Wikimedia Commons (Category: Lingua Libre pronunciation - ara; check the licence on the file page); (2) have a qualified teacher record it; (3) record it yourself in a quiet room.
- To replace one letter: `cd frontend && npm run import:audio -- ba path/to/recording.wav --reader "Name" --licence "CC0" --source "https://commons.wikimedia.org/wiki/File:..." [--reader-type "..."] [--verified-by "Ustadh X"]`. It trims silence, levels loudness, converts to mono AAC, **refuses** a recording that fails the quality check (nothing is changed), and updates `manifest.json` and `CREDITS.txt`. Then run `npm run check:audio && npm run check:audio:quality`. Use `--force` only after listening yourself. Never use synthesised speech.
